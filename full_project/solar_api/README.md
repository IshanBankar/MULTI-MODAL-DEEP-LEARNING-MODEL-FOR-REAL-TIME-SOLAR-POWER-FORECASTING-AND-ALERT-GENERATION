# Solar PV Forecasting API

A FastAPI service that serves **live inference** from the trained multi-modal
solar power forecasting model (2-layer LSTM + 5-feature met encoder + 3-block
CNN on satellite imagery → early-fusion regression head).

This wraps the research model from the paper *"Multi-Modal Deep Learning for
Real-Time Solar PV Forecasting"* in a production-style API: a caller sends a
24-hour time-series window, current meteorological readings, and a satellite
image patch, and gets back a next-hour power forecast in kW.

## Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Liveness check + loaded model metadata |
| GET | `/predict/sample/{position}` | Runs inference on a real held-out sample (Nov–Dec test period) and returns predicted vs. actual kW — good for demos |
| POST | `/predict` | Runs inference on a caller-supplied 24h window + met scalars + satellite image (base64 PNG) |
| GET | `/docs` | Interactive Swagger UI (auto-generated by FastAPI) |

## Run locally

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Then visit `http://localhost:8000/docs` for the interactive API explorer, or:

```bash
curl http://localhost:8000/health
curl http://localhost:8000/predict/sample/500
```

## Run tests

```bash
pip install pytest httpx
pytest tests/ -v
```

## Run with Docker

```bash
docker build -t solar-forecast-api .
docker run -p 8000:8000 solar-forecast-api
```

## Deploy (Render / Railway / Fly.io)

All three support "deploy from Dockerfile" directly from a GitHub repo:

1. Push this folder to a GitHub repo.
2. **Render**: New → Web Service → connect repo → it auto-detects the
   `Dockerfile` → set port to `8000` → deploy.
   **Railway**: New Project → Deploy from GitHub repo → auto-detects
   `Dockerfile` → deploy.
3. Once live, your `/health` and `/predict/sample/{n}` endpoints are public —
   put the URL in your resume/portfolio and link to `/docs` for a live demo
   reviewers can click through without writing any code.

## Notes on the model

- Checkpoint: `data/best.pt` — trained `concat`-fusion model, all three
  modalities (`ts` + `met` + `img`) enabled, loaded exactly as saved by
  `train.py` (architecture config, encoder order, and target
  normalisation stats are all read from the checkpoint itself).
- `data/norm_stats.json` — training-set z-score statistics, applied to
  incoming requests before the forward pass and inverted on the output so
  responses are in real kW, not normalised units.
- `data/demo_slice.csv` + `data/demo_slice_images.npz` — a trimmed slice of
  the Nov–Dec test period (with a 24h lookback buffer) bundled specifically
  so `/predict/sample/{position}` can demo real inference without shipping
  the full 8,760-row / 38MB dataset.
- Typical inference latency after model warm-up is **~3–5ms/request** on
  CPU, matching the 3.8ms/sample figure from the paper's real-time
  deployment claim.
